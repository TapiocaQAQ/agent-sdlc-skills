# Δ — 枚舉這一輪改過的每一行

抽樣式的審查者——外部 AI、人工 review、隨機探測——**在結構上找不到
「你剛寫的那個修正不夠寬」**,因為那個位置看起來已經處理過了,沒有人會回頭再抽同一個地方。
但它同時是整份 diff 裡**命中率最高**的位置:寫下那個修正的人,幾分鐘前才剛被證明
在那一條軸上想得不夠寬。

這一關的存在就是為了枚舉那個母體。**它不是另一輪審查。**

## 何時用

- 第 10 關 `/agent-sdlc:external-ai-review` 跑完之後、第 8 關 `/agent-sdlc:commit-message` 之前。
- 任何**至少採納了一條發現**的審查輪之後。
- 使用者說「你自己檢查過了嗎」「Δ」「枚舉這輪改過的行」。

**只有第 9/10 關採納了_零_條發現時才跳過**——那時母體是空的,在進度檔寫「Δ 空,已跳過」。

> ⛔ **沒有「若需要」這個選項。** 採納了任何一條,這一關就是強制的。
> 2026-08-09 實測:⏭ 那行憑記憶被手寫成「Δ(若需要)」,而那一輪採納了 9 條,Δ 差點沒跑。
> 檢查一下自己是不是加了規則裡沒有的軟化詞(「若需要」「視情況」「可選」)。

## 1. 用機械方法定義母體——不要憑記憶

母體是**第 5/6/7/9/10 關在_這一輪_改過的每一行**,不是整個 diff。導出它,不要回想:

```bash
# 上一顆 commit(或審查前的快照)對現在的工作樹。
git diff <你在 gate 5 之前存下的那份 diff> HEAD
# 或者,當這一輪是疊在某個 base 上、尚未 commit 的工作時:
git diff main -- <這一輪動過的檔案>
```

若審查前的狀態有存一份 diff 到 scratch(**建議在 gate 5 之前先存一份**),
就還原一棵乾淨的樹再對打。把導出的**檔案數與 ± 行數寫進進度檔**——那個數字就是這一輪可複驗的依據。

然後把它拆開:**可執行變更** vs **註解／文件／控制**。兩者都在範圍內。
散文只要在**定義觀察窗、覆蓋宣稱、或某條保證**,它就等同於可執行——
那是下一個人會拿來相信、而不是重新量測的東西。

## 2. 枚舉兄弟值——不要再抽樣一次

對母體裡的每個決策點,枚舉它的**兄弟**:相鄰拼法、邊界值、同一條軸的其他成員、
同一個位元組的其他編碼。拿它們去打**真正的程式路徑**;不要用推理代替。

實測案例——這些是抽樣沒抓到、枚舉抓到的:

- 一個綁在兩條逐字字串上的守衛 → 尾斜線那個兄弟照樣把真的 Bearer token 轉發出去。
  **而為那個修正新寫的兩條控制只送了那兩種拼法,所以兩條都印 PASS。**
- 同一個守衛從逐字比對改成**前綴**比對——仍然是位元組比對,而軸是**段落身分**。
  再多 3 個洞(`//auth/...`、`auth./...`、`auth../...`),全部帶著憑證。
- 再下一輪改成枚舉整條位元組軸:`_ALLOWED_PATH_BYTES` 的**全部 67 個 byte**
  逐一接在被守的前綴後面、打真正的判定鏈 → **0 條轉發**。
  **「我測了 8 種拼法」和「這條軸關上了」的差別就在這裡。**

⚠️ **枚舉「那條軸」只有在軸畫對的時候才有用。** 枚舉之後同一個形狀還在復發,
那是軸畫錯了,不是樣本數不夠。

## 3. 升級門檻——按性質,永遠不按數量

**升級**的條件是:≥1 條發現**會實際走到危險路徑,或推翻某條已經寫下來的保證**。
那會觸發一次完整的第二次 gate 7(`/code-review max -fix`),
而且**Δ 不准自己修那一類**——那種缺陷需要的是完整審查,不是剛寫出這個 bug 的同一顆腦袋順手補一刀。

nit、風格、可讀性建議**永遠不升級**,不論幾條。

> 數量在這裡是壞指標:一個會把憑證帶出機器的洞,本身就足以證明這一輪的判斷寬度不夠;
> 而三條 nit 湊出來的升級只是白跑一次 gate 7。

## 4. 未達門檻的:當場修,然後 Δ′(最多兩趟)

當場修掉。然後跑 **Δ′**:同樣的枚舉,但母體**只有 Δ 自己剛剛改過的那幾行**。
上限**兩趟**。

> 🔴 **為什麼准修,以及為什麼這樣仍然會終止。** 舊規則寫的是
> 「只報告、絕不 auto-fix —— **這是讓遞迴終止的那一條**」。
> 那是把**終止**綁在**不修**上,但兩件事可以拆開:遞迴會爆炸是因為
> 「修 → 重新枚舉**全部** → 再修」沒有上界,**不是因為「修」本身**。
> Δ′ 的母體只有 Δ 動過的行、而且只跑一趟——上界是常數。
>
> 舊規則的實際代價(2026-08-09 實測):Δ 抓到的三條全部未達門檻,於是照規則**原封不動**進了 commit
> ——「已知是錯的、而且已經寫下來了」的句子進了版控,只為了維持一條其實不需要的紀律。
> 而新規則下 Δ′ 第一次跑就**當場抓到第四條**,同一類,是在修第三條的時候寫下的。
> **那一條如果不重掃,不會有任何一關看到它。**

⚠️ **Fagan 的 Follow-up 精神保留,沒有丟掉**:進度檔必須把
**Δ 修了什麼**與**Δ 留給人審什麼**記成兩份分開的清單。
第 11 關人審驗的是這兩份清單,不是憑印象。

## 5. 寫進進度檔

必須留下:

- **母體**:哪幾行(檔案數、± 行數、怎麼導出的)
- **枚舉了什麼**:那幾條軸與它們的兄弟集合
- **發現**:幾條,以及每一條的類別
- **門檻**:達到與否,以及判斷理由
- **Δ 修了什麼** / **留給人審什麼**——兩份分開的清單
- **Δ′ 結果**,以及它在兩趟上限內收掉了

⛔ **「Δ 跑了但沒發現」和「Δ 沒跑」在檔案上必須長得不一樣。**

## 反模式

- **把 diff 重讀一遍找「有沒有哪裡怪怪的」**——那是又一輪抽樣。Δ 是對一個**指名的**母體做枚舉。
- **只枚舉可執行的那些行。** 2026-08-09 那一輪裡,那個典型失效復發的 4 次
  **全部**是關於觀察窗或覆蓋邊界的**散文**宣稱,而且都是在修別的東西的當下寫下的。
- **把外部審查乾淨的一輪當成「修正夠寬了」的證據。** 那只代表 reviewer **用抽樣**沒找到新東西。
  實測:一輪以 0 blocker / 0 warn 收尾,緊接著 Δ 抓到 3 條、Δ′ 再抓到第 4 條。
- **在這裡修達門檻的發現。** 升級它。
